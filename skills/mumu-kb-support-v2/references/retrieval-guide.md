# 实时检索手册 (retrieval-guide)

> 木木知识库实时检索的方法手册。知识条目、制度解读和门店基础信息通过「钉钉 AI 表格」实时读取；已授权的企业知识库原文（如门店指引、活动/退款规则）通过文档检索实时读取，禁止依赖静态快照。
> baseId: `3NwLYZXWynKpDxYvsNAzk5GZVkyEqBQm`

## 0. 检索总原则

1. **AI 先做来源路由**：不要固定“实时优先”或“AI 表优先”。由模型按语义选择 `realtime`、`aitable`、`both` 或 `general`；无法确定时用 `both`。
2. **实时性**：进入实时路由后现场读取授权企业知识库原文；活动退款规则不再读取 AI 表，原文更新即可生效。
3. **从窄到宽，多候选合并**：先精确（filters 二级主题），一路放宽到全库扫描；每一层的结果都是候选，必须合并后再由 AI 按用户语义、适用城市、标题/内容相关度做最终判断，**最后一级才是兜底记缺口**
4. **过滤硬规则**：每条命中记录都要核对——发布状态=已发布、失效时间未过、回答边界合规
5. **多源交叉**：制度类问题 = 知识条目（事实）+ 制度解读（解读）；门店基础信息走门店信息表；卡项、活动、退款、前台 SOP 等实时变化规则走企业知识库原文

## 2. 检索方法与示例

### 方法 A：精确过滤（优先）

按「二级主题」或「一级业务域」过滤，适合意图明确的问题：

```json
// filters: 二级主题 = 分红与收入
{"operator":"and","operands":[{"operator":"eq","operands":["8Nt63ZQ","分红与收入"]}]}
```

### 方法 B：全文关键词（放宽）

把问题里的关键词直接传给 `keyword`（常见问法命中率最高）：

```
keyword = "发薪" / "分红起算" / "差评" / "筋膜枪" / "会展中心"
```

### 方法 C：组合（关键词 + 过滤）

关键词 + 二级主题双保险，减少噪音。

### 2.1 检索降级阶梯（查不到就放宽，最后才兜底）

> 核心原则：**宁可多查两级，不要轻易记缺口**。每一级命中都只是候选，不可直接停止；完成召回后统一比较候选，再决定是否需要继续扩大范围。

| 级别 | 检索方式 | 说明 | 示例（问题："深圳店长能不能也开分店？"） |
|------|---------|------|------------------------------------------|
| 1 | filters 二级主题精确 | 按意图映射的二级主题过滤 | 二级主题=开店与门店发展 |
| 2 | keyword 原文关键词 | 直接拿问题里的关键词全文搜 | keyword=开分店 |
| 3 | keyword 换词/精简 | 口语化改写、去修饰词、换同义表达 | keyword=分店 / 店长 或 深圳 |
| 4 | filters 放宽到一级业务域 | 比二级主题宽一档的维度 | 一级业务域=内部政策示例（或员工合伙制） |
| 5 | 全库扫描 | **不传 filters/keyword**，分页遍历知识条目表（limit 100 逐页），逐条比对「用户意图/常见问法」与问题的语义匹配 | 遍历 200 条，人工比对"店长开分店" |
| 6 | 仍无命中 | 才进入第 5 层兜底：通用建议 + 记缺口 + 转人工 | — |

**全库扫描执行要点**：
- 用 query_records 不带 filters/keyword，limit=100 + cursor 翻页，直到取完全表（约 200 条，2~3 页）
- 扫描时重点比对「用户意图」与「常见问法」字段，语义相近即视为命中，不必字面一致
- 全库扫描只用于第 5 级，不做为常规检索手段（token 开销大）

**门店类问题**中，地址/营业状态/店型等基础信息走门店信息表（keyword=店名/区域 + 营运状态=使用中）；卡项、活动、前台 SOP、会员服务等规则走企业知识库「门店指引」实时原文。原文检索必须：① 用原问句、去口语核心词、关键概念分别查询；② 合并所有返回文档；③ 优先标题与核心概念、城市一致的文档；④ 有深圳/上海等城市信息时排除其他城市规则；⑤ 无法确认当前有效期时提示核验，不能把历史活动当作当前规则。

## 3. 命中后的组装规则

1. **答案主体** = 标准答案；流程类补「办理步骤」；条件类补「成立条件 + 例外情形」
2. **高情商化（员工视角）**：制度类问题（薪酬/处罚/退股/晋升/流程）命中知识条目后，**必须**再查「制度解读」表（按关联知识编号），用五个字段组装员工视角答案：
   - 「员工关切」→ 在心里确认提问者的担心（共情素材，不说破）
   - 「背后逻辑」→ 解释为什么这么定（员工视角转述）
   - 「对员工的意义」→ 对提问者的好处
   - 「员工成本与限制」→ 如实讲代价，不粉饰
   - 「推荐表达」→ 首选话术（软化版答案）
3. **标注边界**：依据等级=效果推导 的解读要标注"这是制度解读而非原文"；高风险条目要带谨慎提示
4. **不利制度必给出路**：涉及处罚/退股/降档/限制类答案，结尾必须给申诉/证明/例外路径（「例外情形」字段），给不了的明确转人工
5. **多记录冲突**：取更新版本（适用制度版本数值大者优先）；无法判断 → 转人工
6. **文末来源标注（固定格式，写原文不写编号）**：回答结束后单独一行 `回答内容来源：<知识条目原文名称>、<知识条目原文名称>`，如 `回答内容来源：风险金共同存入、分红优先级、单店风险金总额`。规则：名称取知识条目的「用户意图」字段原文（如"风险金共同存入"）；只出现在这一行，正文不得提及任何编号；多记录命中用顿号列全；制度解读参与回答时不单列（解读服务于知识条目）

## 4. 更新维护说明

- 表格数据更新即实时生效，**无需改动本技能包**
- 若发现检索不到但提问高频 → 确认是否已写入知识缺口表
- 若某二级主题下找不到对应记录 → 检查是否该主题为空/未建条目，必要时反馈补知识
