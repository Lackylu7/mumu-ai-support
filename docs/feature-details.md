# 功能与业务逻辑

## 1. 意图识别和业务域路由

机器人先判断用户是在查询制度/流程/资格/经营数据等企业知识，询问机器人能力或请求普通写作、翻译、分析，反馈上一条答案不准确，还是明确要求转人工。

业务问题再通过关键词、主题和候选业务域进行路由。路由结果包含最小置信度门槛；低于门槛时不强行缩小检索范围，而是保留更宽的候选集。

## 2. 证据优先回答

1. 从 AI 表格或授权知识库获取原始记录。
2. 过滤未发布、待审核或已失效内容。
3. 将记录转换为统一的 `Evidence` 对象。
4. 对冲突、缺字段、数字条件和适用范围做规则校验。
5. 只有通过证据门禁，才把证据交给模型生成自然语言。
6. 输出来源、版本、适用条件和不确定性。

模型不能自行补齐缺失制度；证据不足时返回澄清或人工确认。

## 3. 多问题处理

仅当消息是 2~6 行、每行都像完整问题时才拆分。每个子问题独立检索和回答，最后按原顺序合并，避免把一段普通叙述误拆成多个问题。并发 worker 数量受控，避免突发消息压垮下游服务。

## 4. 人工案件闭环

以下情况会进入人工流程：没有足够的已发布证据；同一问题存在冲突答案；涉及高风险数字、资格、退款或权限；用户明确提出转人工；下游知识服务异常且无法完成交叉核对。

案件会保存原问题、机器人回答、证据摘要和转人工原因。机器人可以创建答疑群、@人工负责人，并在静默模式下避免继续刷屏。人工确认后，结果可以回流到知识审核流程，形成“问题 → 人工结论 → 知识候选 → 审核发布”的闭环。

## 5. 知识导入和审核

知识库支持结构化记录导入、来源/主题/适用范围/版本字段、草稿/待审核/已发布/已废弃状态、缺口记录、候选答案、解释层迁移和兼容旧字段。候选内容不能直接覆盖已发布知识，必须经过审核门禁。

## 6. 可靠性能力

- 请求超时和有限重试；
- Stream 断线重连；
- 幂等键和重复消息抑制；
- 会话级并发锁；
- 心跳和 stale 检查；
- Windows 任务计划程序下的守护与重启；
- 运行日志和业务回答分离，避免把敏感消息写入通用日志。
