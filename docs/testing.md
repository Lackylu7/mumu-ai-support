# 测试策略

## 测试分层

- 领域模型：验证字段、枚举、序列化和状态迁移。
- 知识层：验证导入、审核、候选门禁、查询条件和 payload。
- 服务层：验证意图分流、证据门禁、人工转接和多问题合并。
- 运行层：验证心跳、状态、重启判定和 Windows 脚本预览模式。
- 集成边界：用 fake model、fake gateway 和固定响应隔离外部网络。

## 本地验证

```powershell
.\\.venv\\Scripts\\python.exe -m pytest -q
```

公开镜像只保留不包含真实业务数据的离线测试；完整内部测试仍留在私有工作区，不随公开仓库发布。这样既能展示工程质量，也不会把企业知识或人员信息带进 Git 历史。

## 回归重点

每次修改后重点检查：

1. 证据不足时是否会转人工，而不是自由回答；
2. 旧版本知识是否仍能被兼容读取；
3. 重复消息是否保持幂等；
4. Stream 断线后是否能恢复并更新心跳；
5. 运行脚本的 Preview 模式是否不修改系统任务；
6. 异常信息中是否包含 API key 或完整内部 payload。
